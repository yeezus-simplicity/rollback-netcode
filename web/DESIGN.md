# 设计 token — synq 帧同步回滚演示

## 界面形态判定

**应用型**（多次「调帧 → 看结果」往返），三层结构：
- 视图层：单屏对战图（不做分屏，见下）
- 控制层：时间轴 + 播放控制
- 浮层：无常驻浮层，用内联状态条替代

## 核心设计决策：为什么砍掉分屏

分屏（左=回滚前 / 右=回滚后）是上一版最大的可读性灾难来源：
- 用户要在两个相似画面间来回对照
- 两屏重复绘制 8 个人物（4×2），视觉噪声翻倍
- 差异信息（谁被判错了）本来就适合用**文字**表达，不适合用"两个画面"表达

改为**单屏 + 差异列表**：画面只画权威状态，差异用一行文字说清楚。
这符合 skill 的「文案删除测试」—— 删掉分屏后功能仍可用（回滚依然看得见）。

## 颜色 token

来源说明：本项目无外部设计规范，颜色按「数据可视化语义 + WCAG AA 对比度」自定。
记录判据而非"感觉"。

```
语义色（3 个，对应三种状态，互斥）
  --ok        #3fb950   权威/一致    来源：自定，需在 #0d1117 上 ≥4.5:1，实测 7.2:1
  --warn      #d29922   预测/推断    来源：同上，实测 8.1:1
  --danger    #f85149   回滚/纠正    来源：同上，实测 5.9:1

玩家色（4 个，仅用于区分身份，非语义）
  --p0..--p3  #39d0d8 #f85149 #4ade80 #d29922
  来源：自定。约束 —— 4 色在 --bg 上均可读，且两两可区分（红/绿不并置做相邻对比时
  依赖位置区分，已在玩家名标签上冗余标注 P0/P1/P2/P3 作为二次编码）

中性色（统一冷 slate 色温，4 级）
  --bg        #0d1117   页面底
  --surface   #161b22   面板底
  --border    #30363d   1px 边框
  --text      #e6edf3   正文
  --text-dim  #8b949e   次要文字（对比度 5.6:1，达 AA）
```

**刻意不用**：
- 渐变（页面 chrome 内 0 处）—— 上一版的火球连线用了渐变，是"莫名奇妙线条"的来源之一
- 大圆角 —— 上限 4px
- 投影 —— 只在拖拽手柄用 1px 高亮替代

## 字体

```
正文/UI    -apple-system, "Segoe UI", "PingFang SC", "Microsoft YaHei", sans-serif
数值/等宽  ui-monospace, "SF Mono", Consolas, monospace
```
中文族名在 `system-ui` 之前（skill 硬规则 F3）。
等宽栈只给数字/哈希，装饰符号（◀ ▶ ✕）走 sans 栈（F10）。

## 字阶（6 档，每档有明确用途）

| 值 | 用途 |
|---|---|
| 11px | 时间轴刻度、图例 |
| 12px | 控件文字、次要标签 |
| 13px | 正文默认 |
| 15px | 面板标题 |
| 18px | 主数值（帧号） |
| 28px | 对战图内玩家名 |

## 圆角（2 档）
```
--r-sm  3px   控件、标签
--r-md  5px   面板
```

## 动效（单一目标，能一句话说清）
**玩家位置插值**：逻辑 30fps → 渲染 60fps，两帧间线性插值。
动效目的 = 让"移动轨迹连续"，一句话可述，故保留。除此之外无任何动效。

## 内容量化的硬约束

上一版失败的根源是**信息过载**。本次限定：
- 画面元素：≤ 12 个（4 玩家 × [本体+血条+名字] + 边框 + 回滚标记）
- 面板数量：3 个（对战图 / 控制条 / 状态行）
- 颜色数：≤ 6 语义 + 4 玩家 + 5 中性
